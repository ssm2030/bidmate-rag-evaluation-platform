## 1. Batch Operational Standard (Fixed 20 Units)
모든 배치는 토큰 효율과 데이터 품질 유지를 위해 **20개 단위**로 작업하며, 아래의 **5-Batch Cycle 루프**를 엄격히 준수한다.

### [5-Batch Cycle: 유형 x 난이도 자동 배분표]
AI는 현재 작업 중인 배치 번호(N)에 해당하는 행의 개수 설정을 그대로 실행하라. (5개 배치마다 한 세트가 완료되며, 각 유형별로도 완벽한 5:3:2 비율이 형성된다.)

| 배치 번호 (Mod 5) | 유형 A (6개) | 유형 B (8개) | 유형 C (2개) | 유형 D (2개) | 유형 E (2개) | 배치 합계 (20개) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **B1, 6, 11...** | 하3, 중2, 상1 | 하4, 중2, 상2 | **중1, 상1** | 하1, 중1 | 하2 | **하10, 중6, 상4** |
| **B2, 7, 12...** | 하3, 중2, 상1 | 하4, 중2, 상2 | 하2 | **중1, 상1** | 하1, 중1 | **하10, 중6, 상4** |
| **B3, 8, 13...** | 하3, 중2, 상1 | 하4, 중2, 상2 | 하1, 중1 | 하2 | **중1, 상1** | **하10, 중6, 상4** |
| **B4, 9, 14...** | **하3, 중1, 상2** | **하4, 중3, 상1** | 하1, 중1 | 하1, 중1 | 하1, 하1 | **하10, 중6, 상4** |
| **B5, 10, 15...** | 하3, 중2, 상1 | **하4, 중3, 상1** | **하1, 상1** | 하1, 중1 | 하1, 중1 | **하10, 중7, 상3** |

## 3. Execution Rules (중복 및 편향 방지)
1.  **Metadata Integration**: `primary_rfp_id` 및 `comparison_rfp_ids` 정보를 별도 컬럼이 아닌, 기존 **`metadata_filter` JSON 컬럼** 내부에 포함하라.
2.  **No-Boilerplate**: 공통 입찰 규정 질문을 지양하고, 해당 RFP 그룹만의 **특수 기술 사양, 예산 세부 내역, 독소 조항**을 집중 타격하라.
3.  **Specific Binding**: 질문 내에 기관명과 사업명을 반드시 포함하여 정답의 특정성을 확보하라.
4.  **Ranking Logic**: 유형 B의 경우, nDCG 측정을 위해 `ground_truth_docs` 리스트의 0번 인덱스에 가장 핵심적인 근거 문서를 배치하라.
5.  **CSV Formatting**: `history` JSON 및 `ground_truth_answer` 내의 큰따옴표(")는 반드시 이스케이프하거나 작은따옴표(')로 대체하여 CSV 구조 파손을 방지하라.
